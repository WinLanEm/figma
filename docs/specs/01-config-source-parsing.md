# 01: Config/source parsing

## Задача

Научить CLI принимать входные данные: токен Figma, источник иконок и настройки. Источник - один из трёх вариантов: file key, Figma URL или library key. Источник и настройки можно задавать через CLI-флаги или через `iconsync.config.json`. За один запуск - ровно один источник.

## Решение

Модуль `src/config/` из четырёх частей.

- `env.ts` - чтение `FIGMA_ACCESS_TOKEN` из окружения. Готово.
- `config-file.ts` - чтение и валидация `iconsync.config.json` (Zod).
- `source.ts` - определение источника: `fileKey` / `url` / `libraryKey`. Из URL достаём `file_key` и `node-id`.
- `index.ts` - общий экспорт модуля.

Правило приоритета: CLI-флаг перекрывает значение из конфига. Если источник не задан или задан два и более раз - ошибка с понятным текстом и exit code 2.

Валидация схемы - через Zod. Ошибки парсинга и валидации оборачиваются в свой тип ошибки, чтобы CLI мог отдать корректный exit code.

## Приёмка

- `npm run check` зелёный.
- Тесты покрывают:
  - чтение корректного `iconsync.config.json`;
  - ошибку на битом JSON;
  - ошибку на неверную схему;
  - разбор `--file-key`, `--url`, `--library-key`;
  - извлечение `file_key` и `node-id` из Figma URL;
  - ошибку, если источник не задан;
  - ошибку, если задано больше одного источника.
