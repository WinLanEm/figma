# Workflow

## GitHub flow

- `main` защищена, прямые push запрещены.
- Одна задача в таск-трекере → одна ветка → один Pull Request.
- Ветки: `feat/A-03-naming`, `fix/S-07-safe-delete`.
- ID задачи из таск-трекера обязателен в названии ветки.
- Коммиты: `feat(figma): add batch export`.
- Merge: squash, зелёный GitHub Actions, минимум один approve.
- SVG и `.iconsync/manifest.json` коммитятся вместе с изменением дизайна.
- `.env` и `.iconsync/logs/` никогда не коммитятся.

```text
Задача -> branch -> код + тесты -> self-review -> PR -> review -> merge
```

## Задача и PR

Задача в таск-трекере содержит цель, приёмку, зависимости и оценку в часах. Задачу больше 12 часов сначала дробим.

В PR указываем:

- что сделано;
- как проверить;
- что не входит в задачу;
- ссылку на задачу в таск-трекере.

Рискованные изменения manifest/удаления требуют ревью тимлида. Рефакторинг не смешиваем с функцией без необходимости.

## Spec

Spec — короткий план решения конкретной задачи до начала реализации. Он нужен для нетривиальных задач, когда разработчику полезно заранее показать подход и получить согласование. Для мелких и очевидных изменений Spec необязателен.

Файл: `docs/specs/<TASK-ID>-short-name.md`.

```md
# TASK-ID: Название

## Задача

Что и зачем меняем.

## Решение

Как собираемся реализовать.

## Приёмка

Как проверить результат.
```

## ADR

ADR фиксирует важное принятое решение и причину: например, почему выбрали библиотеку A вместо B. Его задача — помочь будущему разработчику или AI быстро понять контекст и не предложить заново уже отвергнутый вариант.

ADR нужен, когда решение дорого менять, оно неочевидно и были реальные альтернативы. Файл: `docs/adr/NNNN-short-name.md`.

```md
# Короткое название решения

Выбрали A вместо B, потому что ... . Последствие: ... .
```

Spec и ADR должны быть конкретными и компактными: без пересказа задачи, общих фраз и текста ради объёма.

## Definition of Done

- Критерии задачи выполнены.
- Есть тесты на основной сценарий и ошибки.
- Проходят typecheck, lint, test и build.
- Документация обновлена, если поведение изменилось.
- В логах и fixtures нет токенов.
- Межмодульное взаимодействие идёт через публичные интерфейсы и именованные DTO.
- Нет импортов внутренних файлов другого модуля; изменение контракта отражено в Spec или PR.
- PR одобрен не автором.

## Что проверять на ревью

1. Нет записи вне `outputDir` и удаления вне manifest.
2. Фильтр не затрагивает иконки вне своего scope.
3. Ошибки понятны и возвращают правильный exit code.
4. Результат не зависит от порядка ответа Figma или ОС.
5. CLI, Figma и файловая логика не смешаны в одном файле.
6. При частичной ошибке старые SVG сохранены, удаления отложены, exit code ненулевой.
